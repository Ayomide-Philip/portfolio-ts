# Objectives

Before writing any code, scaffolding files, or installing dependencies, create a clear, well-structured Product Requirements Document (`PRD.md` for new products, or `docs/<feature-name>.md` for features) that defines what is being built and get the user's approval.

## Core Principles

- Understand before documenting.
- Never invent user requirements.
- Distinguish confirmed decisions from assumptions.
- Adapt discovery to project complexity.
- Obtain explicit approval before implementation.
